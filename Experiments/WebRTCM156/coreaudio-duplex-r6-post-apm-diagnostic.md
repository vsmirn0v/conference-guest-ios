# R6 DEBUG custom capture postprocessing diagnostic

This app-only follow-up uses the frozen SDK ef48 and stacks on the f81 recording-demand follow-up. It changes no DSP settings, capture/publication gates, factory, SDK binary, canonical dependency or default backend. It is called only by the opt-in diagnostic harness.

`GuestSystemAudio.installPostAPMDiagnosticForTesting()` explicitly sets the existing module's capture postprocessing delegate once, outside recording windows. The SDK initializer ignores its delegate argument; the SDK property is weak, so the owner retains the tap strongly. `beginPostAPMDiagnosticRecordingForTesting()` preallocates and arms one phase, returning `GuestPostAPMTestRecording`. `endPostAPMDiagnosticRecordingForTesting(recording)` removes that phase while holding the same admission lock as the bounded callback copy, then closes/drains the recorder. Only after successful closure may `recording.finish(to:)` write a file. An open recorder refuses export. Detach runs on audioQueue; the SDK setter takes the same lock held through Process, so the tap remains strongly retained until nil is installed and observed. Full shutdown also detaches before releasing the factory. Uncertain cleanup retains ownership.

The tap copies full-frame deinterleaved float-S16, without modifying the SDK buffer. PCM16 WAV retains actual initialized rate and mono/stereo channels; scale32768 means16384 is0.5. The seam is after AEC/NS/AGC2/post-filter, before APM post-level adjustment, first-unmuted-frame zeroing and Opus. It is not the final encoder input.

All PCM and timing storage is preallocated. Callback code uses try-lock admission and bounded copies, with no disk I/O, owner/module queries or setter calls. File and timing serialization occur only after copy admission closes/drains. The unchanged SDK adapter itself allocates an RTCAudioBuffer wrapper per delegated call and may skip Process under setter contention. These facts are labelled in evidence; collector sequence is not proof of every APM call.

The WAV contains PCM `data`, then a RIFF `ctim` chunk: little-endian u32 version1/u32 count followed by32-byte rows {u64 sequence,u64 PCM frame offset,u64 callback uptime nanoseconds,u32 frames,u32 reserved0}. No timing rows are truncated. Total WAV bytes, including all timing rows and headers, are capped at12,000,044. Response metadata contains offsets/schema/count rather than the full timeline. Callback times are receipt-clock measurements, not acoustic sample timestamps; accepted PCM is concatenated without concealment or resampling, and ctim preserves the wall-clock mapping.

Eligibility requires nonempty capture, stable format/initialization, no clipping/nonfinite samples, rejected/capped/contention-dropped callbacks or sequence gaps, and finite ordered arm/close times. First callback delay, callback-to-callback gaps, and final callback-to-close gap must each be at most50ms. Actual admission time is recorded after preallocation/recheck. Failed eligibility is retained as diagnostic evidence, not a qualified recording.
