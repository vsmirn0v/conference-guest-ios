# R6 semantic receive-demand reconciliation

App-only follow-up to the immutable R6 SDK ef48fbe7 and the create/typed-input-proof follow-ups. The default and old-SDK paths are compiled without the R6 flag. No hardware, SDK, factory, native policy or consent change.

The failed Host49 run finished initial output-only Prepare just before AudioReceiveStream::Start published playout demand. R6 generic ADM Start is intentionally demand-only, so an additional semantic control wakeup is required.

Two finite event sources cover both orderings:

* Completed subscriber answer applies remote and local SDP. SdpOfferAnswerHandler applies session state and posts BaseChannel::EnableMedia_w before local-description completion. The later native Prepare worker bookend orders behind that work. This also covers inactive/active renegotiation and receiver removal.
* Ordinary RTCRtpReceiver first-packet notification follows worker AddRecvStream/SetPlayout and the synchronous AudioReceiveStream::Start -> AudioState::AddReceivingStream -> ADM StartPlayout path. Empty-SSRC streams may be created only on the first packet, so SDP completion alone is insufficient. Notification happens before decoded audio and is backfilled by native SetObserver. It is a wakeup, not proof that demand is active; native demand and typed physical proof remain authoritative. The different network-thread receptive-change notification is not used as a readiness fence.

Each peer retains exactly one observing wrapper and delegate per native receiver identity until close. Duplicate wrappers never replace that observer. Retention and active membership are installed before SetObserver, whose backfill may be synchronous. Removal revokes that membership without destroying or replacing the observer. Re-add uses a new membership permit. A callback captures its membership permit before scheduling actor work; queued work cannot adopt the replacement membership. Close revokes all memberships and clears handlers/delegates before closing the PC, then releases retained wrappers. Existing unobserved duplicate-wrapper destruction is protected by the SDK's _observing guard.

The engine owns one MainActor coalescer per subscriber and system-audio owner. An event marks one pending pass. Events during an await coalesce to one additional pass. An empty next() clears running in the same actor turn, so no wakeup can be lost at task completion. Each iteration checks subscriber identity, coalescer identity, failure/Leave state and a permanent revocable permit before and after await. Leave/failure revoke immediately, cancel the task and clear the peer handler. Cleanup awaits the existing task before peer destruction and factory retirement. There is no timer poll, reconnection or repeated hardware attempt after native failure.

The permit is checked again on audioQueue and at each latest-intent Prepare iteration. Latest native Sound/mute/Leave authority is unchanged. Receive hints never authorize capture: when input is authorized but no immutable typed input proof has succeeded, the hint defers without calling Prepare. Only explicit activateMicrophone starts the first input transaction under its original deadline. Already prepared input may be preserved during output reconciliation. Successful activation itself reconciles latest output. If an admitted activation ends without typed input proof and no newer admitted activation owns that obligation, the engine atomically closes the same live owner and synchronously reports failure before throwing. This prevents Session's withdrawn-request exception rule from hiding a stranded unprepared owner. Admission uses unique request tokens on every exit; an older failure cannot revoke a newer same-sequence activation. Never-admitted permission rejection and already-prepared input do not claim unresolved-owner failure. There is no fallback Prepare; recovery policy may require an explicit rejoin rather than automatic recovery. The new control operation has a ten-second aggregate bound including a preceding input transaction's queue time; HAL work remains on audioQueue, never the notification callback, MainActor or WebRTC worker.

Verification boundaries: the Foundation-only exact helper fixture covers dirty handoff/cancellation/concurrency; the synthetic Peer test invokes the public delegate directly to cover app wrapper identity, duplicate wrappers, remove/re-add, no decoded-PCM dependency and queued close suppression. It does not exercise native RTP-to-observer delivery. Native callback ordering/backfill is source-reviewed, not simulated as a live RTP proof. Actual guest meetings must still demonstrate late-demand output startup and the held completion fault cases. AirPods timing/quality remains unqualified by these tests.
