# CoreAudio owner retirement r5

This separate candidate layers on [diagnostic r4](coreaudio-diagnostic-r4.md). It addresses safe retirement after an invalidating route callback. It provides no converter recovery, automatic reconnect, factory replacement or new default backend. The observed r4 failure was native `-6`, stream-format origin 10, selected output device 93, during an output 48000→24000 Hz transition with unchanged input/output IDs. Those are observations; no names, device IDs, rates or profile labels drive this implementation.

The candidate root is `.build/bluetooth-aec-validation/coreaudio-retirement-r5`. Its source preimages were frozen and compared with r4 before editing. Final patch, lock, source overlay/manifest, build evidence and tests bind this root after review/build. Frozen r3/r4 SDKs, raw failed runs and canonical dependency locks remain separate.

## Retirement contract

The native first-error record remains immutable forensic evidence. Every later non-route error also updates a separate sticky unsafe mask/count, so a route error cannot hide a failed stop, destroy, callback drain, converter disposal or listener removal. Unsafe state never clears. The old owner cannot initialize, start or unmute again after invalidation or retirement.

The explicit `retireExperimentalCoreAudioOwner()` permanently closes capture authority and retires both directions. A successful result requires separate native stop/destroy statuses for each started IOProc, the matching registration acknowledgment, closed callback admission and drained admitted callbacks, joined workers, removal of each successfully owned listener, converter disposal and discarded ring history. Ownership is recorded as resources are acquired, including partial initialization. A signaled event or cached running flag alone is insufficient. Timeout remains unsafe even if a callback later returns. Any uncertainty retains the owner and blocks another physical capture owner.

After direction cleanup, the operation removes and drains the global device listener, checks `AudioHardwareUnload`, and disposes owned semaphores. Only then can native `retirementConfirmed` become true. The R5-only Swift shutdown path requires this proof and zero unsafe failures before releasing the factory and owner lease. It does not clear the original error or reopen the retired ADM.

`nativeDiagnostics` exposes each direction's observed/required proof masks and native stop/destroy statuses. Status `-2147483647` means not attempted, not success. Proof bits are: created 1, started 2, stop succeeded 4, destroyed 8, admission closed 16, callbacks drained 32, worker joined 64, converter disposed 128, listeners removed 256, direction clean 512. The required mask reflects acquired resources. `cleanupUnconfirmed` stays true for unsafe failures or an invalidated owner that has not completed retirement; the original route error remains available after proven clean retirement.

## Callback lifetime

The new Mac-only experimental module type constructs `AudioDeviceMac(true)` before any Init. Its listener and IOProc registrations use durable callback cells, including the global listener installed before application opt-in. Its native callbacks receive no raw owner `this` as client data. AudioConverter callbacks are synchronous inside admitted IOProc/worker calls and are bounded by those lifetimes. The ordinary constructor preserves legacy registration and lifecycle behavior; no runtime migration is attempted.

A cell's single atomic combines a closed bit, a once-published bit and entrant count. Successful CAS admission acquires the immutable owner pointer; a stack lease releases the count after the last owner access. Retirement closes admission before observing zero entrants. A queued callback arriving afterward accesses only its tombstoned cell. Rejected output callbacks silence supplied native buffers without reading the owner. Cells cannot reopen or be reused.

The process has 1024 fixed cell slots in static storage that is not destructed during process teardown. Allocation occurs on the control path. Capacity exhaustion fails setup explicitly; there is no raw-pointer fallback or unbounded allocation. Exact cell size is exposed by native diagnostics and checked by the hardware-free suite. Cells retained after unregister are intentional bounded tombstones, not active audio owners. Listener admission opens before native Add can notify; failed Add closes admission immediately and defers draining until retirement outside the Init mutex.

A separate fixed 128-slot native registry anchors the complete ADM and its attached AudioDeviceBuffer before Init or peer-factory exposure. Failed factory creation cannot destroy callback-visible state before Swift owns a factory. A slot releases only after complete native/module retirement, with a local scoped reference protecting the release transaction. Failed proofs retain the complete owner; quarantined factory failures consume bounded capacity until process exit. Capacity exhaustion returns no experimental factory before registering resources. The nullable initializer handles this explicitly and prevents automatic ADM fallback. The new construction also blocks I/O initialization/start until explicit control is enabled. Legacy platform ADM and canonical/default VPIO remain on their existing paths.

## Validation and limits

The exact final source passed Astra review, compiled with two build jobs, and passed all 39 hardware-free C++ tests. Tests cover a paused admitted callback, queued callbacks after owner destruction, tombstone no-reopen, cell and whole-owner capacity exhaustion, whole-owner retention after factory failure, confirmed-only anchor release, a later unsafe failure after the route first error, independent stop/destroy results, every required retirement proof, partial initialization and permanent Init rejection after invalidation/retirement. Existing private-input, capture-epoch and ring tests also pass. The tested cell size is 16 bytes, so 1024 cells occupy 16384 bytes plus fixed pool metadata. No unit test opens audio hardware.

Four memory-only Swift variants also pass: R5 default, R5 with all retirement/diagnostic/private/stopped flags, and frozen r4/r3 with the older CoreAudio/private flags excluding R5. Run the new variant with `Experiments/NativeGuestTests/run-system-audio.sh <r5-xcframework>/macos-arm64 --retirement-audio-experiment`. The suite compiles the nullable experimental initializer and checked shutdown but never creates a factory or probes devices. Source comparison checked 7711 files with no unexpected deltas, and independent zero-fuzz patch reconstruction matched final bytes. Frozen r4 binary and canonical SDK lock hashes were rechecked unchanged.

Runtime safe-retirement qualification passed in frozen Host47 actual Mac tests: the Bluetooth output-format invalidation retained its first error while stop/destroy statuses were0, proof1023 covered required508 for both directions, unsafe failures were0, retirementConfirmed=true and physical I/O stopped. Healthy built-in and mixed-route owners, reconnect and default VPIO compatibility also passed. Full Bluetooth microphone activation still fails on format change; these results do not qualify route recovery or a default-backend switch. See [bounded hardware report](../../docs/native-mac-bluetooth-acoustic-validation-2026-10-27.md). R5 still rejects route-changing activation. Diagnostic route queries instrument timing and provide no matched latency claim. Older r3/r4 app builds avoid R5 methods through the separate capability-gated `ROCK_COREAUDIO_RETIREMENT_R5` define. No canonical pin or publication is changed.
