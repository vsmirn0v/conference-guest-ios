# Private input requested-mono contract r3

This experimental increment layers on [private-input r2](private-input-experiment-r2.md), with the same DEBUG/build/runtime gates and built-in/original-output-running restriction. Canonical dependencies, normal meeting VPIO/cache/publication checks, and frozen r1/r2 candidates remain unchanged. No VPIO/output fallback or route broadening is included.

[Patch](private-input-experiment-r3.patch) and [lock](private-input-experiment-r3.lock.json) bind all three preimages/final files to r2. Reconstruct r2 first, verify baselineSHA256, apply with `patch --batch --forward --fuzz=0 -p1 --input <absolute-r3-patch>`, then verify final hashes. Independent reconstruction used zero fuzz; all referenced source files were compared for unexpected deltas. Build/test/package with the r1 recipe and locked arguments into a new root. Byte-identical rebuilding is not claimed; required upstream/toolchain/base source inputs are not duplicated.

Select local `.build/audio-startup-followup/private-input-r3` explicitly with `NativeMacGuest/build.py --framework-root`. APIs and capabilities are unchanged. The private builder intentionally requests Float32 mono at the initial rate/interleaving. Seal retains the exact pre-start native bus comparison. Running admission requires BOTH actual input bus and sink input AVAudioFormat to exactly equal that requested format. Only after all thirteen startup predicates pass does the graph adopt that verified private bus baseline. Commit rechecks adopted baseline, requested endpoints, unchanged route/owner generations and existing closed publishing gates. No ADB/NetEq/public formats are changed.

The private C++ format contract is immutable after configuration/adoption. All28 no-device tests pass, including endpoint rate/channel/Float32/interleaving rejection, rejection when ANY startup predicate is absent (including same route), and post-adoption drift/rebase rejection. Existing lifecycle/revocation/stop quarantine tests remain included. No test opened hardware.

Retained `startupDiagnostics` schema and proof-mask bits remain as r2, except bit12 now means both endpoints exactly match the requested private mono format, rather than the pre-start native channel layout. A failed route still prevents adoption. Diagnostics during work are approximate atomic observations; use stable post-failure/post-stop readback. generationAfter is retirement-time when Finish overwrites it. Meter values still disappear on revoke; retained counters carry no PCM/level or permission.

The stable built-in PS-pilot on r2 retained routes77/70, successful native engine/unit start and accepted mono callbacks at44100Hz. Its proof mask4095 showed every condition passing except the initial3-channel versus negotiated1-channel format equality. This attributes the private format rejection; earlier AirPods route switches remain separate correct rejections. R3 full private-check acceptance is pending. Treat this as a candidate format-contract correction, not a shipping pin. Physical input-off restoration, output continuity, no private remote audio and the next cached network activation still need actual Mac proof.
