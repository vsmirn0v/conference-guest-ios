# Catch up on missed meeting speech

The in-call **Catch up** panel marks time when the phone may not have played meeting audio. It reads transcription messages already supplied to the guest by the provider SDK. Transcript text is shown with speaker and time when the SDK supplies them, and lines arriving after reconnect are merged by message ID. The app never labels the recovered text complete: an absent line may mean silence, disabled transcription, delayed history, or lost data.

The timeline opens a suspected missed interval when CallKit holds the meeting for another call, iOS reports an audio interruption, the SDK leaves its active phase, or the phone loses its network path. Overlapping reasons form one interval; it closes only when every reason has cleared. The conference microphone and camera controls continue to follow the existing call lifecycle. The new panel does not activate either stream. A new meeting starts a fresh timeline; reopening the same meeting after an unexpected disconnect retains the timeline until the user intentionally leaves.

When the SDK does not expose transcription to the guest or the host has it off, the panel shows the interruption time and says that no transcript is available. An unrecognized provider timestamp is displayed separately and never attributed to a gap. This matters because a timestamped transcript line is evidence of that line, not evidence that all speech in the interval was captured.

The current SDK's public interface exposes ASR-tagged chat messages and view permissions, but no supported incoming PCM capture callback, independent playback gate, or time-range recording retrieval. The provider says transcription may require organizer capabilities and a business license. In the anonymous test room, the signed iPhone build reported that this guest cannot view a transcript. See the [provider's transcription guide](https://developers.sber.ru/help/jazz/guide/call-administration) and [Apple's interruption guidance](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions).

The current-room index is saved in the app's support directory with iOS file protection and excluded from backup. An app restart turns unobserved time into a suspected connection gap. The join screen lets the user review and delete that local history before rejoining. Explicit Leave deletes the file; a saved index older than 24 hours is discarded on the next launch. Neither the invitation password nor call audio is stored. The index has bounded transcript and interval counts and marks when older entries are discarded.

**Current boundary:** the user chose an iPhone-only app without a separate capture companion. This local index cannot recover a phone-network outage if the provider does not retain and return the missing speech. It does not offer accelerated audio replay without a supported source and playback control. In the tested anonymous room, it can report suspected missed time but cannot reconstruct the words. The panel intentionally reports unavailable coverage rather than inventing a recap. There is no summarizer yet; the available transcript is presented verbatim.

If the provider later grants transcript history to anonymous guests, a supported history API can fill network gaps. Until then, iPhone-only audio replay requires a supported SDK hook that delivers incoming PCM before audio output is interrupted and a means to keep receiving it while held. Neither is available in the pinned public interface. Apple speech recognition cannot recover audio that the phone did not receive.

## Acceptance checks

1. In a room where the host has enabled transcription for this guest, speak numbered phrases before, during and after an answered phone call. Verify the interval timing, speaker attribution, late-arriving lines and explicit coverage warning against a second participant's record.
2. Repeat after disabling the phone's network path long enough for SDK connection loss, then reconnect and rejoin. Verify that previously unseen transcript messages appear only if the provider supplies history; otherwise the panel must say they were not recovered.
3. Repeat in a room without transcription. Check that the missed interval remains visible without fabricated text.
4. Check overlapping CallKit and audio-session interruptions, repeated holds, route changes, manual Leave, a different meeting link, and a terminated app. The first two should make one gap; a new meeting must not inherit the previous room's transcript.

On iVitalii, an opt-in UI test requested a real CallKit hold and unhold transaction without an incoming cellular call. It passed: the panel marked one missed interval and reported no recovered transcript. A separate UI test opened the panel in the anonymous room and confirmed that transcript access was unavailable. Another device UI test terminated the app during the test hold, relaunched it, reviewed the persisted missed interval before rejoining, and deleted local history. These tests do not establish behavior under a competing cellular call or a real network outage.
