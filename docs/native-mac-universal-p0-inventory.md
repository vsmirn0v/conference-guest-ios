## Entry points and ownership

These are source-reachable paths, not runtime observations. Links point to their controlling source; capture, lease and recovery outcomes still require instrumented validation.

| Entry or action | Current path | Media/session authority and qualification boundary |
| --- | --- | --- |
| Standalone invitation or Home | `NativeDesktopWorkspace.joinInput` / `join` resolves a `JoinDestination`, then `makeMeeting` constructs `NativeDesktopMeetingModel` ([workspace](../NativeMacGuest/DesktopWorkspace.swift), [model](../NativeMacGuest/DesktopMeetingModel.swift)). | Model chooses Guest, Telemost, TrueConf or Rock engine. Each retains its own connection and feature logic. |
| Saved invitation, favorite, recent, Calendar and reminder | Workspace installs `library.onOpenMeeting` to call `join`; Calendar resolves a meeting and can attach event metadata. Scheduled join is rejected while another meeting is active; explicit reminder Join can add one. | Same `join` / model path; scheduled admission has separate cancellation and completion. Preserve calendar identity and guard behavior. |
| Handoff and continuation | Workspace's `continuation.onJoinTarget` enters `join`; prepare/resume/leave callbacks act on the relevant model. `continueActivity` resolves continuation separately. | Same model after target admission. Source hold and target connect are coordinated externally; do not equate successful admission with proof of media or confirmed source departure. |
| Multiple meetings | Workspace keeps `meetings`, creates a model per meeting and installs `microphoneArbiter` calling `claimTalk`. | Production source defaults to `SharedAudioEngine.shared`, with a separate attachment per meeting. Talk role is coordinated by workspace and shared audio; device safety depends on mute/epoch and teardown barriers. Inspect actual runtime before asserting a single active owner in every path. |
| Companion preview | `NativeMacGuest/App.swift` accepts a ticket and constructs `CompanionMeetingController`; [controller](../NativeMacGuest/MeetingController.swift) constructs `GuestSession` directly and attaches `SharedGuestMeetingAudio` to the shared engine with exclusive-talk admission. | This is a distinct session path, not a `NativeDesktopMeetingModel`; it must migrate separately. The legacy direct-audio branch is compiled only for Debug or `NATIVE_LEGACY_AUDIO`. |
| Presenter and screen share | `DesktopMeetingModel.startSharing` selects Guest's dedicated publication or a native screen source plus `engine.setScreenTrack`. `DesktopPresenterSession` owns Presenter capture and UI coordination. | Model currently creates and retires shell capture. Presenter and share stop participate in Leave; Guest, TrueConf and Rock have different publication semantics. |
| Camera and private checks | Model uses `NativeDesktopCameraLease.shared` for live camera; [device settings](../NativeMacGuest/DesktopDeviceSettings.swift) requests private camera and audio checks. | Private camera can borrow the live track. Pinned SDK audio uses `SharedPrivateAudioCheck`; the unpinned private-check path can create a `GuestSystemAudio` only after its suspension coordination. `NativeDesktopMediaService` is still reached from settings and model, so it is not proven dead code. |
| Assistant and transcription | Workspace associates assistant services with model; [AttentionCoordinator](../NativeMacGuest/Attention/AttentionCoordinator.swift) dispatches through model actions. [LocalTranscription](../NativeMacGuest/Attention/LocalTranscription.swift) has both native WebRTC and LiveKit audio bridge types. | Voice action requires model/talk-role gates; Guest-specific participation and feature code accesses the concrete engine. Source-level path alone does not qualify physical audio. |
| MCP | `App.swift` constructs `NativeDesktopMCPService(workspace:)`; its backend operates through workspace and active models ([service](../NativeMacGuest/MCP/NativeDesktopMCPService.swift), [backend](../NativeMacGuest/MCP/NativeDesktopMCPBackend.swift)). | MCP is a control entry into existing workspace/model paths, with its own permission checks. It is not a separate conference media engine. |

For regular Release builds, [SharedAudioEngine](../NativeMacGuest/Engines/SharedAudioEngine.swift) states that the shared engine is enabled; Debug and explicit legacy comparison builds may select another route. Guest, external sessions and Rock accept this shared owner; [Rock's bridge](../NativeMacGuest/Engines/SharedAudioEngine+LiveKit.swift) installs its factory and observer into the patched SDK. Rock also creates a render factory in [its engine](../NativeMacGuest/Engines/NativeDesktopRockEngine.swift), so one physical audio owner does not mean one factory or one peer.

Current recovery executors are `GuestSession`, `NativeDesktopExternalSession` and the LiveKit Room respectively. There is no evidence in this inventory that the different executors have been unified. Model teardown includes concurrent engine abort when startup is pending, followed by drains for controls, Presenter, share, peers and camera lease.

## P0 diagnostics and measurement evidence

The uncommitted P0 changes add a bounded `Media ownership` entry to the existing Copy/Export Diagnostics report. It contains a snapshot of shared audio attachments, random process-local owner/lease/factory/module generations, lease-registry counts, workspace camera reservation state and workspace session/share generations. Effective sender state is explicitly unavailable: reading the SDK sender may block on the RTC worker. Each attachment reports the last completed wrapper command and registered sender count; SDK or native track changes outside that wrapper can make this command witness stale, so it is not evidence of current transmission or remote silence. The report uses cached state and does not read a factory after retirement. It contains neither invitation URLs, credentials, SDP, room titles nor PCM. IDs are process-local and need not correlate workspace sessions with independently generated audio attachment IDs. The configured recovery executor is a source-derived label, not proof of the SDK's internal retry state. The companion bypasses the workspace model and its camera lease; this snapshot alone cannot prove physical companion camera activity or hardware-owner uniqueness.

The subsequent diagnostics extension includes native provider connection/retry generations, Guest attempt generations, Rock room revision and render-factory presence, Presenter capture/lease retirement bookkeeping and companion camera intent. These are cached control-plane observations; Rock's SDK-internal retry generation and the companion's actual camera hardware activity are unavailable. The expanded source passed 91 selected tests in an unsigned Debug host (`.build/universal-p0-compile/p0-diagnostics-v2-tests.xcresult`), and the separate GuestSession harness passed 31 deterministic scenarios. It is not present in signed build 112.

The [baseline record](evidence/native-mac-universal-p0-baseline.json) uses the [version 1 schema](schemas/native-mac-engine-baseline-v1.schema.json). Measurements deliberately carry null values and `not-run` until a controlled scenario has actual evidence. Record the build identity, route, independent peer, conditions and raw results for each real measurement; avoid embedding meeting data or private invitation links. P0 code syntax and the standalone audio-lease diagnostic check were verified locally, but the full app diagnostics have not yet been built or run on the signed baseline.
