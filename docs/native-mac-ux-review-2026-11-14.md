# Rock’N’Roll for Mac: UX and design review

Reviewed 14 November 2026 against the native Mac source at beta 106, the supplied screenshots, and existing test coverage. The accompanying interactive design drafts are discussion prototypes, not shipping screens. Text, sample people, dates and meetings in the drafts are illustrative. Priorities below represent proposed product priorities, not measured frequency or impact.

This is a source-led review, not a complete live usability audit. In particular, real meetings, device changes, VoiceOver, the installed update, cloud sync, production services and the beta 106 voice repair were not exercised as part of this review. Existing accessibility labels, tests, and safety checks are useful evidence but do not by themselves establish a good user experience. A historical assistant screenshot suggests some intent misunderstandings; it is not evidence that the same behavior is present in the current beta.

## Product direction

Make it easy to answer three questions at every point: **Where am I? What will this action affect? What should I do next?** The strongest simplification is a clearer relationship between a room that can be rejoined, a particular meeting's record, and the assistant's activity within it. Keep the existing capabilities and cautious sending behavior; expose technical settings and unusual actions progressively.

The app has valuable foundations worth keeping: microphone and camera start off, the live view identifies the meeting holding the microphone, the share banner exposes Stop sharing, the assistant can show why and what it will send, notes have local save recovery, and model recovery distinguishes a confirmed storage error from an unknown cause. The redesign should preserve those behaviors rather than flattening everything into a single switch.

## Priority findings

### P1 — Recoverability, trust and actions with consequences

1. **Make voice deletion explicit and truthful.** The saved-voice row has an immediate Delete button ([VoiceCloneViews.swift:229](../NativeMacGuest/Attention/VoiceCloneViews.swift#L229)); `deleteVoice()` ignores file removal errors and clears the in-memory record ([VoiceClone.swift:394](../NativeMacGuest/Attention/VoiceClone.swift#L394)). A user can lose an enrolled voice without an undo, or see it disappear when the file could not actually be removed. Ask for confirmation for the saved voice, say that the downloaded model is separate, retain the UI state and surface errors if deletion fails. Keep targeted cache repair separate from both deletion actions.

2. **Explain what happens when the user takes over.** “I’ll answer” pauses assistant following/participation and yields the turn; the returned pause token is discarded. “Done” closes the composer without explicitly resuming it ([DesktopMeetingWorkspaceLive.swift:314](../NativeMacGuest/DesktopMeetingWorkspaceLive.swift#L314), [DesktopMeetingWorkspaceLive.swift:323](../NativeMacGuest/DesktopMeetingWorkspaceLive.swift#L323)). Do not silently resume an assistant that the user paused. Instead show “Assistant paused while you answer,” its current state after Done, and an explicit Resume action where applicable. Confirm the exact restoration rules in a real call before changing them.

3. **Scope privacy claims to the operation.** Assistant settings say “Audio never leaves this Mac” ([AttentionViews.swift:855](../NativeMacGuest/Attention/AttentionViews.swift#L855)); the call has a microphone and the product supports speaking a reply into a meeting ([DesktopMeetingView.swift:373](../NativeMacGuest/DesktopMeetingView.swift#L373), [AttentionViews.swift:852](../NativeMacGuest/Attention/AttentionViews.swift#L852)). Even if the intended claim concerns assistant-model processing, the global wording can be read as a promise about call audio. State separately what is sent to meeting participants, what is processed locally, and which text or excerpts go to the selected provider. Verify the final wording against the actual data paths, not assumptions about the provider.

4. **Give the same meeting actions in both More menus.** Which menu is displayed changes with screen text selection and gallery paging ([DesktopMeetingView.swift:352](../NativeMacGuest/DesktopMeetingView.swift#L352)). The main menu includes attention instructions, voice reply testing and immersive mode ([DesktopMeetingView.swift:449](../NativeMacGuest/DesktopMeetingView.swift#L449)); the alternate duplicates a shorter list and omits them ([DesktopMeetingView.swift:465](../NativeMacGuest/DesktopMeetingView.swift#L465)). Use one source for menu items and preserve conditional availability. Test both layouts and disabled reasons; do not put a debug/test action in the primary flow just to make the lists identical.

5. **Report transcription setup truthfully.** Selecting a model is separate from downloading it ([TranscriptionSettingsView.swift:58](../NativeMacGuest/Attention/TranscriptionSettingsView.swift#L58)); if an installed selection is not ready, the status says the voice detector is downloading without inspecting that detector’s actual download/error state ([TranscriptionSettingsView.swift:17](../NativeMacGuest/Attention/TranscriptionSettingsView.swift#L17)). Present selected, downloaded, downloading, failed, and ready as distinct states; give a precise Retry or Download action when applicable. Choosing an uninstalled model should not appear to be ready. Preserve the existing model until an intentional change succeeds if engineering validation supports that flow.

6. **Make assistant output targets and approvals legible.** The assistant can send an outcome to a meeting and already identifies the target and asks for confirmation ([AssistantOutcomeViews.swift:323](../NativeMacGuest/Attention/AssistantOutcomeViews.swift#L323)). Extend this distinction consistently to read/search, writing private memory, drafting, sending chat and speaking into a meeting. Always show the destination, proposed content, and approval state before an external action. Test ambiguous requests; do not infer current failures from old screenshots.

### P2 — Findability and navigation

7. **Fix calendar recovery routes and empty states.** “Choose calendars” selects Settings but does not select its Calendars tab ([DesktopHomeView.swift:398](../NativeMacGuest/DesktopHomeView.swift#L398), [DesktopHomeView.swift:517](../NativeMacGuest/DesktopHomeView.swift#L517)); it can open General or the last-used unrelated tab. Set the intended destination explicitly. When permission is denied, settings currently show an explanatory sentence ([DesktopHomeView.swift:497](../NativeMacGuest/DesktopHomeView.swift#L497)); offer the appropriate macOS privacy settings route and a refresh/recheck where supported. Distinguish no access, no calendars selected, loading, no supported invitations and no upcoming meetings.

8. **Make saved rooms and meeting records distinct.** The top-level sidebar contains Recent meetings, Meeting workspace and Assistant ([DesktopWorkspace.swift:8](../NativeMacGuest/DesktopWorkspace.swift#L8)). Recent is a history of rejoinable rooms ([NativeDesktopLibrary.swift:41](../NativeMacGuest/Data/NativeDesktopLibrary.swift#L41)); Workspace → Review browses recorded sessions and conversations ([DesktopMeetingWorkspaceReview.swift:30](../NativeMacGuest/DesktopMeetingWorkspaceReview.swift#L30)); Assistant → Outcomes separately browses notes and outcomes ([AssistantOutcomeViews.swift:40](../NativeMacGuest/Attention/AssistantOutcomeViews.swift#L40)). As a design hypothesis, test clearer labels such as “Saved rooms” and “Meeting history,” plus a shared session header and links between transcript, notes, outcome and tasks. A common front door does not require merging data stores, losing per-room instructions, or deleting the focused/parallel workspace.

9. **Give search and Home honest states.** Favorites and Recent share a single search value and render an unannotated empty list when no rows match ([DesktopHomeView.swift:8](../NativeMacGuest/DesktopHomeView.swift#L8), [DesktopHomeView.swift:387](../NativeMacGuest/DesktopHomeView.swift#L387)). Keep the query visible, use separate state or clear it deliberately on destination change, and distinguish an empty library from no matches. Home shows a Today heading whenever *any* future supported calendar meeting exists, even if the subsequent today-only filter yields no rows ([DesktopHomeView.swift:326](../NativeMacGuest/DesktopHomeView.swift#L326), [NativeDesktopLibrary.swift:52](../NativeMacGuest/Data/NativeDesktopLibrary.swift#L52)). Gate the heading on the same filtered collection, or show a useful “No meetings today / next meeting tomorrow” state.

10. **Make personal tasks discoverable without inventing ownership.** Tasks are under Assistant → My Tasks ([AttentionMomentsView.swift:24](../NativeMacGuest/Attention/AttentionMomentsView.swift#L24)) and require an explicit owner-name setup before rows are shown ([PersonalTasksView.swift:56](../NativeMacGuest/Attention/PersonalTasksView.swift#L56)). Test a clearly labeled Tasks destination or a Home summary and a brief in-context name confirmation; preserve the confirmed-identity rule, meeting provenance, completion, archive and undo. An empty state should explain whether there are no tasks, a filter is active, or identity setup is needed.

11. **Make first-run setup skimmable and recoverable.** The setup sheet has Calendar, Reminders and Devices steps, a single Finish later action, and no visible step count ([DesktopHomeView.swift:558](../NativeMacGuest/DesktopHomeView.swift#L558)). Show progress, what each permission enables, a clear per-step Not now, and how to return later. Do not request a permission before the relevant action or turn on cloud sync, reminders or handoff merely to make the flow shorter.

12. **Use progressive settings.** Settings has nine top-level areas in a horizontal tab view ([DesktopHomeView.swift:469](../NativeMacGuest/DesktopHomeView.swift#L469)); Assistant then combines attention behavior, situations, local model status, roles, profile, providers, voice and privacy in a long form ([AttentionViews.swift:654](../NativeMacGuest/Attention/AttentionViews.swift#L654)). Try a searchable sidebar with concise overview rows and focused pages for Assistant behavior, AI providers/privacy, Transcription and Voice. Put rare routing, debugging, model paths and connection choices in advanced disclosures. Preserve every current setting, per-meeting override and privacy explanation; do not change defaults as part of a navigation redesign.

### P3 — Polish and consistency

13. **Reduce competing emphasis in Home and live workspace.** Home combines up to two immediate meetings, join form, favorites, recent rooms, calendar rows and status messages ([DesktopHomeView.swift:272](../NativeMacGuest/DesktopHomeView.swift#L272)). Favor one clear next-meeting action and the invitation field, with secondary sections below. In a live workspace, distinguish the selected conversation from the meeting that owns the mic; multiple meeting cards and parallel transcripts should remain available ([DesktopMeetingWorkspaceView.swift:167](../NativeMacGuest/DesktopMeetingWorkspaceView.swift#L167)). Test narrow windows and large type before settling on a fixed layout.

14. **Keep status close to the affected item.** Notes already expose saving, saved, retry and draft export ([MeetingNotesView.swift:119](../NativeMacGuest/Notes/MeetingNotesView.swift#L119)); integrate that status with the meeting header rather than obscuring it behind a generic global alert. Exports have queued, paused, partial and conflict states ([ObsidianSettingsView.swift:22](../NativeMacGuest/Obsidian/ObsidianSettingsView.swift#L22)). Use user-facing status words and direct recovery actions, and call the one-way direction “Export updates to Obsidian” rather than implying two-way sync. Preserve conflict review, paused queues, and manual export.

15. **Make technical integrations approachable without hiding trust boundaries.** MCP presents endpoint, pairing and read/write tool lists with explicit approval and revocation ([NativeDesktopMCPSettingsView.swift:14](../NativeMacGuest/MCP/NativeDesktopMCPSettingsView.swift#L14)). Show connection state and paired clients first, with detailed endpoint/tool lists in disclosures; retain per-action approval, scope visibility and revoke. Updates already show installed version, channel, download/check preferences and no-downgrade explanation ([NativeDesktopUpdates.swift:263](../NativeMacGuest/Updates/NativeDesktopUpdates.swift#L263)); retain these in the redesigned system section. In reminders, offer readable minute-based presets alongside the current precise seconds controls ([DesktopReminders.swift:44](../NativeMacGuest/DesktopReminders.swift#L44)) without rounding stored custom values.

## Draft screen mapping

The accompanying interactive drafts illustrate these concepts, not a proposed implementation contract:

- **Home:** clear Join by link, next meeting, compact upcoming/room sections, and recovery states. Preserve explicit mic/camera-off prejoin messaging and cross-device handoff choices.
- **Live:** meeting identity, route and capture state stay visible; transcript and assistant controls remain distinct; takeover shows paused state and a deliberate resume action. Preserve share-stop, multiple meetings and private vs meeting-bound output.
- **History:** one session-focused entry point with transcript, notes, outcome and tasks linked to the same meeting; retain room rejoin and existing search semantics. Do not imply that every older session has a transcript or outcome.
- **Assistant settings:** group behavior, model roles and privacy into scannable sections, retain each provider and permission setting, and show actual local/remote destinations.
- **Voice recovery:** known disk shortage can show measured availability and a defensible estimated minimum; ambiguous Neural Engine errors remain ambiguous. Offer retry and narrowly scoped repair independently from Delete model and Delete voice. Keep existing downloaded model and saved voice during repair. No mock value is a real measurement.

## Decisions and validation before implementation

- **Navigation architecture:** compare current labels, cross-links and a unified session entry with five to eight people performing rejoin, locate notes, locate transcript and find an assigned task. Measure successful first destination and time; do not remove the workspace or room favorites on assumption alone.
- **Trust and control:** with test meetings, ask users to distinguish private draft, memory write, chat send and spoken reply; validate explicit target and whether an assistant is paused after takeover. Exercise active, background, multiple-meeting and detached-window states.
- **Recovery and data preservation:** test no-space on each relevant volume, generic errors, retries after space is freed, cancelled downloads, cache repair, deletion failure and restart. Verify the actual saved voice and downloaded model survive a real repair using safe backed-up fixtures; never claim an exact specialization requirement if the OS does not provide one.
- **State coverage:** exercise first run, denied/revoked permissions, no data, no search matches, loading, offline/provider failure, partial export, conflicts, update pending, and data save failure. Verify that links open the exact destination and offer a fallback when system settings cannot open.
- **Accessibility and localization:** inspect at minimum supported window size and a narrow window, light/dark appearance, long English and Russian text, text scaling, keyboard-only operation, VoiceOver names/state/order, focus restoration, contrast and reduced motion. Avoid relying on color alone for mic, recording, assistant and error states.
- **Acceptance evidence:** keep the current focused automated suites and add targeted tests for the calendar route, truthful detector state, menu parity, deletion failure, takeover status and localized recovery actions. Then validate live audio, screen sharing, handoff, integrations and upgrade behavior on signed builds; no mockup or source inspection establishes those outcomes.

## Explicit boundaries

These are recommendations and draft designs. No product code, defaults, model files, meeting records, enrolled voices, permissions, connected services or published releases were changed as part of this review. Consider model/provider costs, user consent and the existing remote-action approval boundary before any implementation. Local and server-side data paths must be checked independently before making privacy promises.
